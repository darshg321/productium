# v1.2 handoff: foundation done, mechanical work next

The architectural core of v1.2 is in place and tested. What's left is mostly moving callers onto it and deleting
the old types. Read `v1.2_plan.md` (intro, Part 0, B.0, T) first. Principles that decide close calls:

- **Time is the base.** Everything with a time is an `Entry`. Don't add a timed type; add a field only if a real
  prompt needs it.
- **Don't over-structure for the model.** Refs and a few verbs; open values. Never add a refusal: if something is
  risky, it goes through `BoxApplier.risk` (held for Approve / Decline).
- **Clean break.** No migration or compatibility code. If old code is in the way, delete it.

Run core tests:

```sh
export PATH=$HOME/.local/swift/swift-6.2.1-RELEASE-ubuntu24.04/usr/bin:$PATH
cd Packages/ProductiumCore && swift build --build-tests && swift test --skip-build
```

310 core tests green at handoff. The v1.2 eval cases pass 14/14 with reference answers, and 14/14 **on Sonnet** through
the new box (`scripts/inbox-eval/run.sh --v12`, two full runs in a row).

**Keep test runs small.** After a change, run only what it touches: one test class (`swift test --skip-build
--filter BoxOpsTests`) or one eval case (`./run.sh --v12 <id-part>`). Run the full core suite and the full `--v12`
once at the end of a handoff step, not after every edit. `App/` only compiles on CI (`ios-compile`), so keep App edits small and obvious.

## Mechanical work, in order

Keep core tests green at the end of each step. Delete each old type as soon as its last caller is gone (O10).

1. **Strip compatibility code.** `ChangeLog.swift` `Legacy` / `proposals` decoding; `DayRule`'s bare-array decoding
   and `plainWeekdays` once unused; `ExportBundle.read`'s `"productium-backup"` branch. Add an `ExportTests` case
   that a format-3 file is refused (O5).
2. **Telemetry calls (T2).** Record anything that could be useful (the app isn't released). In App: every box turn
   (`Telemetry.boxTurn` with the message and ops), each replan (duration,
   warnings count, shortfalls), every Health / location / motion read (sample count, error), notifications
   scheduled / answered, `AlarmReconciler` diffs, intents, background launches, save / decode failures. Call
   `state.prune(now:)` where it's already called. Settings → Debug screen (T3).
3. **`isDone` audit.** Where `.isDone` means "still to do / should be planned, nudged or alarmed", use `isOpen`
   (dropped tasks must not be planned or reminded). Where it means "finished", keep `isDone`.
4. **Fixtures as entries.** Add `Fx.timetable: [Entry]` (see `PlannerEntryTests.timetable`) and an `Fx.input`
   overload with entries; move tests off `Fx.school` / `Fx.soccer` as their code moves in steps 5–10.
5. **App wiring (AppModel).**
   - `replan()` (`App/Model/AppModel.swift:158`): pass `entries`, `rules`, `categories`; then
     `PlanEntries.replace(in: &state.entries, with: PlanEntries.from(plan, …), now:)`. At the first replan of a day,
     `state.dayPlans[key] = Accountability.asked(by: plan, on: today)`.
   - `AlarmPlanner.desired`: append `EntryAlerts.alarms(Days.expand(next 3 days), now:, allowed: integrations.alarms)`.
   - Running entry replaces `state.focus`: Start = `TimeLog.start` with `taskId`; Stop = `TimeLog.stop`.
6. **Commitments → entries.** One repeating entry per timetable period under `School › <class>` (source `you`, topic
   = class); spares and lunch `open: true`; other commitments one repeating entry each. `when` → `Repeat.days`;
   `validFrom/Until` → `Repeat.from/until`; `bufferMinutes` goes. Onboarding and Settings write entries. Remove
   `commitments` from `PlannerInput`, `WakePlanner`, `SchoolDay`, `Palette`. `WorkItem.atSchool` /
   `isAtSchoolErrand` go too: errands are tasks, and open time takes light work.
7. **One-offs and calendar → entries.** `oneOffs` → entries. Calendar import writes entries with
   `id: Entry.calendarId(ekId)`, source `calendar`; on re-import keep each entry's `marks`, delete vanished events.
   `ignoredEvents` → `marks[day] = .skipped`. Remove `PlannerInput.events`.
8. **Day changes and situations → skips, detached days and rules.** `DayException`: cancelled = skip, retime =
   `Days.detach` then edit, `wake` = a Rule with `limits.wake` for that day. Situation effects: `busy` → entry,
   `free` → skip / detach, `replace` → skips + new entries, `place` → an entry with `taskId`, `setInput` →
   `Rule.limits`, `mute` → `limits.mute(All)`, `hold` → `notBefore`, `boost` → importance, `note` → About Me. Delete
   `Situations.swift`, `SituationResolver`, `DayOverrides`, `SituationText.swift`, `Exceptions.swift`, `syncNoSchool`,
   and the `o.input(...)` / `o.places` / `o.busy` / `o.free` paths in `Planner.buildDays` (the `lim` paths stay).
9. **Log types → entries.** `markers` (pairs; unpaired starts get the bounded end `TimelineBuilder` uses),
   `outcomes`, `focus`, gap answers → entries. `TimelineBuilder` / `DayTotals` read `TimeLog.past` for the past and
   plan entries for the future, via `CategoryTree.legacy` until Part G replaces the ring. `WorkDone.minutes` =
   entries with `taskId`. Delete `TimelineEvent`, `BlockOutcome`, `FocusSession`, `GapNote` (→ `Telemetry.gap`).
10. **Routines, sleep, alarms (O4).** "Dinner 7:30" is a daily Dinner entry (source `you`); get ready / commute are
    planned entries (minutes = median of your past entries in that category, else today's defaults). Sleep is a
    `plan` entry with `alert = .wake`; the separate wake path in `AlarmPlanner.desired` goes. `AlarmRule` →
    `alert`s (`clock` = an entry with an alarm; `beforeDue` = a task with a time; `shift` / `suppress` = detach or
    skip). Rewrite `AlarmTests` for the `Fx` week. Delete `Routine` storage and `AlarmRules.swift`.
11. **Box in the App (O6).** Core is done (`Box.swift`) and evaluated; this step only switches the App to it.
    - Where AppModel builds the dump request (`DumpApplier.apply` near `App/Model/AppModel.swift:977` and the code
      that calls `Prompts.dump` / `Prompts.dumpContext`): build `BoxContextInput` (state as `BoxState`, `planned` =
      the current plan's entries, `aboutMe`, and a one-line `settings` like the eval's `World.settings`), send
      `BoxTurn.request`, decode with `BoxResult.read(res, timeZone: .current)`, apply with `BoxApplier.apply`, and
      write back `entries / items / rules / categories / dayRules`. Then `BoxTurn.record`, `Telemetry.boxTurn`,
      and `Telemetry.gap` when `result.gap` is set. Log each `result.unreadable` op to telemetry too.
    - `result.facts` → About Me, as the dump's facts are now. `result.queries` → `TimeQueryEngine.run` each, then
      `QueryText.fill(result.reply, results)` is the reply shown; any `problems` go in the receipt.
    - Held ops (`receipt.held`) → an Approve / Decline row in the receipt; Approve = `BoxApplier.apply(held.map(\.op),
      approved: true)`. Undo = `BoxApplier.undo(receipt)`.
    - `setting`, `mood`, `screen_time` ops: `BoxApplier` reports them as "isn't handled here" because they touch
      `AppState` outside `BoxState`. Apply them in AppModel (filter them out before `BoxApplier.apply`), then add one
      line each to the "Ops:" section of `BoxPrompt.system` and rerun `--v12`; it must stay 14/14 and under 6,500
      characters.
    - Delete `DumpPrompt.swift`'s schema / prompt / context, `DumpFields`, `DumpOp`, `Dump.swift`'s applier and the
      old entities once nothing calls them. Keep `Conversation` / `ConversationPolicy` (the box uses them).
11b. **Query tests and charts (F1–F3).**
    - `QueryTests` on a 28-day fixture built from `Fx.timetable` plus logged entries: math class only
      (`categories: ["School › Math"]`), all math (`topics: ["math"]`), by hour, `weekdays`, `confirmedOnly`, and a
      `compare: "previous"` check. Assert numbers, not just non-empty.
    - Six eval cases in a new `V12Queries.swift`, the same shape as `V12Cases` (check = the query the model wrote,
      run through `TimeQueryEngine`, gives the expected total): the six questions in plan Part F. Ask before
      changing a check.
    - App `ChartCard` (Swift Charts) per `QueryResult.chart`; pinned charts store the `TimeQuery` and re-run live.
12. **Phone pickup after bedtime (N, B2).** In `EntryBuilder`, phone use after the planned bedtime becomes a sensor
    entry (id from `Entry.sensorId`), which outranks the planned Sleep, so sleep starts after the last pickup.
13. **UI (O11, B7, G7, G8).** Schedule and Today render `DayEntry`s one way (past / assumed / running / planned);
    every row opens the same entry sheet; swipe right / left to confirm / reject assumed time, a long swipe for a
    range (`Days.confirm(in:)`). Review opens on Today: untracked, assumed, `DayScore` with its parts vs your usual
    day, patterns. Life Metrics lead with minutes tracked, work minutes, deadlines met / missed, scrolling minutes.
    Home is only what's needed during the day.
