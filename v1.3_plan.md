# v1.3 plan: less typing, fewer screens, nothing lost

v1.2 made the time log the base. v1.3 makes it cheaper to keep: one tap from the Lock Screen or a grid instead of a
sentence, Home for "now", Review for "how did today / this week go", and data that survives an uninstall.

Rules for this version (also in `CLAUDE.md`):

- **Work on `dev`, commit as you go**, push `dev` for CI; merge to `main` (a release) only once the `dev` build is green
  and checked with `scripts/test` (simulator smoke run; device run for anything on the Lock Screen).
- **No more clean breaks.** v1.2.2 (`AppState.schema = 4`) is the first version with real data. Every stored change
  from here on migrates it: bump `schema`, add a step in `Migrations.swift`, and a test that decodes a saved 1.2.2
  `state.json` fixture and checks nothing was lost. Never decode an older schema as a fresh state again.
- Every new screen / state gets a `Scenario` (and a `ScenarioTests` case) so it can be checked with `scripts/test`.

---

## Part A: Activity grid (replaces the start-button row)

Today: `QuickStarts` makes a button only after you've started something by text, shows a row of 5, and ranks by
hour / weekday / place. Starting by button is easier than typing, so the buttons should exist from day one and cover
most of a day.

**A1. Templates.** A seed set ships with the app, each with a category, a symbol and a default topic list:
Eating, Walking, Commute, Getting ready, Shower, Homework, Studying, Reading, Class, Practice (instrument / sport),
Exercise, Chores, Errands, Hanging out, Gaming, Social media, Video / TV, Phone call, Nap, Wind down. Templates are
`QuickStart`s with `origin: .template` (yours stay `.you`, the AI's `.ai`). Onboarding shows them; you untick the ones
that don't apply.

**A2. A grid, not a row.** Home shows a 3- or 4-column grid of symbol + word tiles (about 12 visible, "More" for the
rest), the running one highlighted. Tap = start (stops what's running); long press = rename, recategorise, pin, hide.
The same grid is the "What were you doing?" answer for a gap (Part C) and the Live Activity's buttons (Part B, top 3–4).

**A3. Ordered by time.** Ranking is learned from the log: for each activity, how often it started within ±45 min of
now on this kind of day (school / weekend / label), here (place), and after what's just ended; recency-weighted
(half-life ~3 weeks). The top slot is "what you usually do now". Ties fall back to the template order. Pinned tiles
keep their place. (Builds on `QuickStarts.ranked`; add the day-kind and "after X" terms and a decay.)

**A4. The AI keeps the grid tidy.** The weekly insight pass (and the daily taxonomy pass) may: add an activity you
keep typing or that inferences keep finding (e.g. "Bus home" from motion at 15:10), merge duplicates ("Lunch" /
"Eating"), rename vaguely-titled ones, and hide ones unused for 30 days. Applied automatically and logged (Part F);
never touches pinned or ones you renamed / recategorised. Code checks every change (no more than 40 live tiles, no
removal of anything used in the last 14 days).

Done when: a fresh install has a full grid; after two weeks of use the first tile matches what you start at that hour
most days (a `QuickStartTests` fixture), and an AI change shows in the record and never undoes your own edit.

## Part B: Live Activities as the main prompt

Today: a Live Activity only while something runs (`RunningActivity`), and tracking prompts are notifications. A Live
Activity with buttons is the lowest-effort prompt: answered from the Lock Screen or Dynamic Island without opening
the app.

**B1. One "Now" activity, always there.** Replace the running-only activity with a single persistent one whose state
is one of:
- *Running*: title, elapsed, goal line; buttons Stop and Switch (→ the top grid tiles).
- *Untracked since 3:10*: "What are you doing?" and the top 3 grid tiles (A3) + "Other" (opens the box).
- *Assumed*: "Still at School until 15:00?" Yes / No.
- *Question*: an inference question (`Inference.question`) with its one-tap answers.
- *Up next*: "Math unit test · 40 min at 19:00", Start.
Buttons are `LiveActivityIntent`s (they run in the app's process, so they log, replan and update the activity in
place without opening the app).

**B2. Limits we have to design around (free account, no push server).** A Live Activity can only be *started* while
the app is in the foreground or from a `LiveActivityIntent`; without APNs it can't be started or updated by a
server, and iOS ends it after 8 h (12 h on the Lock Screen). So: start / refresh the Now activity when the app goes to
the background, on every intent and button press (each keeps it alive), and from background refresh (update only).
If it has ended, the tracking-prompt notification (D4) is the fallback, and its "Open" restarts the activity.

**B3. Which prompts go where** is the notification setting (Part E): each prompt kind can be "in the Now activity",
"notification", "both" or off. Default: untracked, assumed and questions → Now activity; the morning sleep check and
deadlines → notification.

Done when: on the phone, a whole school day can be tracked from the Lock Screen only (device check by you), and
`RunningActivityTests` cover the state machine (which state wins: running > question > untracked > assumed > up next).

## Part C: Home is "now", Review is "how did it go"

**C1. Home (looked at all day).** Top to bottom: the box; the Now card (running or the grid); "What were you doing?"
for untracked stretches today (moved from Review: each gap with the grid's top tiles as answers); assumed time to
confirm today (swipe / Yes to All, moved from Review); the day ring (Part D); Up Next. Mood faces stay but collapse
into the Now card's corner.

**C2. Review (opened once a day, once a week).** Two segments, nothing else:
- *Day*: today's score and its parts against your usual for this kind of day (median of the last 4), the day ring
  next to your usual day's ring, best / worst hour, and one line of what changed it ("Studying +40 min, Scrolling
  −25 min").
- *Week*: this week vs your last 4 weeks: score per day, tracked / work / deadlines met / scrolling against the
  4-week average, goals closed, How You Work (follow-through, best hours), the leaderboard, the Weekly Note.
Moved out of Review: Where (→ Settings → Places), Life Metrics (→ a "More stats" link at the bottom of Week, not a
card), mood by time of day (→ Week, one line if a pattern is clear; the chart behind it), pinned charts (→ the box's
thread and a "Pinned" list in Week).

Done when: Review has two segments and fits on two screens each; a scenario for each segment (`scripts/test`).

## Part D: Rings like the Fitness app

The current ring is a category breakdown (groups inside, leaves outside, forecast hatched). It answers "where did the
time go", not "how am I doing", and it doesn't look like iOS.

**D1. Three concentric rings, each a goal that closes**, Fitness-style (rounded caps, full-colour track behind at
20% opacity, overlap past 100% with a darker second lap and the end-cap shadow):
- *Work* (blue): minutes worked on tasks vs what today's plan asked (`Accountability.asked`).
- *Tracked* (green): share of waking time that's an entry, vs 100% (the "no gap over 30 min" goal is its subtitle).
- *Limit* (teal → red as it fills): scrolling / unproductive minutes vs your limit; this one is good when it's *not*
  closed, so its label says "18 of 60 min".
The centre shows the time now or the score. Tapping a ring opens its day (the category breakdown moves there, as a
plain sorted bar list, which is easier to read than a second donut).

**D2. Everywhere.** The same rings at small size: the week strip in Review (one triple ring per day, like Fitness's
history), the Live Activity's expanded view, and a home-screen widget later (same extension). Rings close with the
existing celebration (`Rewards`), once per ring per day.

**D3. Accessibility.** Each ring has its word and number beside it (never colour only), works in grayscale (the
v1.1 J rule), and the overlap is drawn, not just coloured.

Done when: `RingModel` computes the three progress values (tests on the `history` scenario) and the simulator shots
show the three rings on Home, Review Day / Week and the Live Activity.

## Part E: One Notifications screen, by severity

Replace Settings → Alarms and the separate notification toggles with **Settings → Notifications**: every kind of
prompt in one list, each with a severity:

| Severity | What it does |
|---|---|
| Off | nothing |
| Quiet | shows in the app (Home) only |
| Live Activity | the Now activity (Part B) |
| Notification | a normal notification |
| Alarm | full screen and sound (AlarmKit), ignores silent mode |

Kinds: wake up, bedtime / wind down, leave for school, session start, missed start, deadline soon, untracked, assumed
time, questions, sleep check, scrolling check-ins, celebrations, weekly note. Each has a sensible default (wake = Alarm,
leave = Notification, untracked = Live Activity, celebrations = Quiet …) and one master "Alarms allowed" switch (the
J rule: nothing becomes an Alarm without you). The AI can suggest a change ("move bedtime to Alarm, you missed it 4
nights") as a line in the record, applied only up to the severity you allow.
Code: one `PromptKind` → `Severity` table in `Preferences` replaces `NudgeSettings` / `AlarmRule` leftovers;
`NudgePlanner` and `AlarmPlanner` read it. (Migrate the 1.2.2 settings: alarms on/off, notification level.)

## Part F: The AI tidies up without asking

Housekeeping the AI does is applied straight away and recorded; there's nothing to approve:
- the taxonomy pass (merge / rename / move categories), the activity grid (A4), category rules, goal nudges, and
  insight-pass setting changes.
- Settings → "What Productium Thinks" → **Changes** shows the record, newest first: what, why (the evidence numbers),
  when. You can undo any line there or by saying it in the box; no Approve / Decline rows, no "Tidy now" button.
- Still held for you (they act on *your* data or wake you up, unchanged from v1.2): the box removing a whole series or
  ≥1 h of time you logged, and anything that would become a full-screen Alarm.

## Part G: Privacy screen goes

Using the app is the consent (onboarding says what's collected, once). Remove Settings → Privacy: "Forget location
history", per-place Forget, and the "Visits kept" count. Places stay, renamed from Settings → Places (moved from
Review's Where). Location history keeps its 180-day trim as housekeeping, not as a privacy control.

## Part H: Data that survives an uninstall, daily backups

iOS deletes the app's container on uninstall, and a free account can't use iCloud containers. Two layers:

**H1. Daily backup files, 3 kept.** Once a day (background refresh, and on launch if the last is >24 h old) the app
writes the full `ExportBundle` to a folder **outside** the app: you pick it once in onboarding / Settings → Backup
(iCloud Drive or On My iPhone → a folder of another app; the app's own folder would be deleted with it). The folder's
security-scoped bookmark is kept so it's written without asking. Files are `Productium-YYYY-MM-DD.json`; after writing,
anything older than the newest 3 is deleted. The write is logged in telemetry; a failure shows in Settings → Backup
and as a Quiet prompt.

**H2. Finding it again after a reinstall.** The folder bookmark is also stored in the Keychain, which iOS keeps after
an uninstall for the same team id. On a fresh install, before onboarding, the app looks for that bookmark: if the
folder has a backup, it offers "Restore from Friday's backup (2,140 entries)". If the bookmark is gone (or the
Keychain was cleared), onboarding has "Restore from a backup file" with the file picker. Restores go through the
migration path (a 1.2.2 backup restores into 1.3).

**H3. Optional off-phone copy.** The same daily file, encrypted on the phone (key in the Keychain), uploaded to the
leaderboard Worker (R2 / KV, one object per install, 3 kept). Off by default. Only worth doing if H1/H2 turn out to
be unreliable on the phone.

Done when: uninstall + reinstall restores everything on the phone (device check by you), `BackupRotationTests` keep
exactly 3, and a 1.2.2 backup fixture restores into 1.3 with nothing missing.

## Part M: Migrations (from 1.2.2 on)

- `Migrations.swift`: `migrate(json, from: schema) -> AppState`, one step per schema bump (4 → 5 …), run on load and
  on restore.
- Fixtures: a real 1.2.2 `state.json` (anonymised from a backup) and the `history` scenario saved at schema 4, in
  `Tests/.../Fixtures/`. Tests: decode → migrate → re-encode keeps every entry, task, goal, category, rule, place and
  setting.
- v1.3's changes that need a step: `QuickStart.origin` / pins (A1), the severity table (E, from the alarm / nudge
  settings), backup folder settings (H1), dropping the Privacy-only fields (G).

## Order

1. M (migration scaffolding + 1.2.2 fixture) first: everything after depends on it.
2. A (templates, grid, ranking), then C1 (Home: grid + gaps + assumed).
3. B (Now activity) on top of the grid. Device check.
4. D (rings), then C2 (Review Day / Week).
5. E (Notifications screen), F (records only), G (Privacy out).
6. H (backups + restore after reinstall). Device check (uninstall / reinstall).
7. Smoke script + new scenarios green on the simulator and the phone; `DESIGN.md`; merge to `main`.
